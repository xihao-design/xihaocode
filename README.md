# 西浩资源库 · xihaocode

把 GitHub、F-Droid 等公开渠道上**值得用的开源资源**，整理成中文条目，并以网盘直取的方式交付。

- 线上站点：**<https://www.xihaouc.top>**
- 本仓库是站点的**唯一真源**：内容数据 + 生成器 + 门禁工具都在这里；`dist/` 由构建产出，不入库
- **纯静态生成、零第三方依赖**：只用 Node 内置模块，克隆下来不需要 `npm install`
- 收录范围只有开源与非商业免费资源。本站不存储、不制作、不修改任何软件与文档，也不提供破解、去广告或商业授权版本

### 1.2 四条原则

| 原则 | 具体做法 |
| --- | --- |
| **逐条核实** | 每个条目都打开官方仓库 / 官方站点确认过协议与维护状态；核不到的标「待确认」，不含糊带过 |
| **不编造** | 拿不到的信息宁可留空，也不用假数据凑数；缺失的图标退化成首字标记，不热链、不占位造假 |
| **网盘直取** | 资源以百度网盘转存分享，提取码在详情页一键复制；同时给出官方仓库地址，建议优先走官方渠道 |
| **无广告无付费** | 站内不设收费墙、不做「关注后获取」 |

### 1.3 一个条目里有什么

- **详情页**：官方仓库、Star 数、开源协议、支持平台、所属分类；百度网盘地址与提取码（一键复制）；「建议先转存到自己网盘」的提示；同分类的其它条目推荐。
- **AI 工具页**：官网、定价页、是否开源、免费额度形态、国内访问情况、是否原生支持中文。
- **技能页**：技能说明、适用场景、打包下载入口。
- **筛选与检索**：分类筛选条、搜索框（按名称或功能匹配）、标签与专题页面。
- **SEO 友好**：每页独立 canonical、面包屑与 JSON-LD 结构化数据，全站 `sitemap.xml` + `robots.txt`。

## 二、使用方法（访客）

### 2.1 找资源

首页「**频道入口**」按频道分流（软件库 / 电脑软件 / AI 库 / 技能库），点进去是该频道的完整列表；
首页往下就是全部开源 App 的资源列表，每张卡片都可以直接进详情页。

### 2.2 筛选与搜索

- 列表上方的**分类筛选条**按分类过滤，计数实时更新。
- **搜索框**匹配名称与功能描述；键盘按 <kbd>/</kbd> 或 <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>K</kbd>
  可聚焦并全选搜索框（直接输入即替换原关键词），清空用搜索框右侧的 <kbd>×</kbd>。
- 想看「跨分类的角度」用**标签**（无广告、离线可用、隐私友好、可自建服务、GPL 系协议…），
  想看「一整套装什么」用**专题**（新机先装、离线优先、数据留在自己手里、开源影音客户端）。

### 2.3 获取资源

进详情页 → 「百度网盘」区块 → 复制提取码 → 打开网盘链接下载。
建议先**转存到自己网盘**再下载：原分享链接失效不影响自己，日后重装也方便。
每条同时也给了官方仓库 / 官网地址，能走官方就走官方。

### 2.4 主题与外观

- 顶栏右侧按钮在 **自动 / 浅色 / 深色** 三态间循环，选择记在本地。
- URL 加 `?theme=dark`（或 `light`、`auto`）可临时预览某一主题，不会写入本地设置 —— 分享和截图很方便。
- 右下角「**外观**」面板可调卡片密度与分类色彩（彩色 / 单色）。

### 2.5 直达入口

| 用途 | 地址 |
| --- | --- |
| 全站地图 | `/sitemap.xml` |
| 爬虫规则 | `/robots.txt` |
| 关于本站（收录标准与核实方式） | `/about.html` |
| 免责声明 | `/disclaimer.html` |
| 版权与侵权处理 | `/copyright.html` |

## 三、技术架构

### 3.1 数据流

```
GitHub开源软件分享知识库.xlsx
        │  tools/extract-kb.ps1
        ▼
   .kb-raw.json ──┐
redesign/curation.json ─┤  build.mjs  ──▶  redesign/dist/  ──▶  EdgeOne Pages
redesign/data/github.json ┘      ▲
redesign/content/*.json ─────────┤（AI 工具 / 技能 / 指南 / 标签 / 专题）
redesign/assets/icons/ ──────────┤
redesign/site.config.json ───────┘（品牌、导航、频道、广告位、统计）
```

`build.mjs` 一次跑完所有页面：首页、127 个条目详情页、分类页、标签页、专题页、
AI 库（目录 + 分类 + 子类 + 详情）、技能库、电脑软件频道、运营指南、自营产品页、联盟跳转页、
合规页与 404，并输出 `sitemap.xml` / `robots.txt` / 静态资源。任何一步失败都会直接中断构建，不产出半成品。

### 3.2 线上产物 + 增量（`redesign/live/`）

样式与客户端脚本以**线上产物**为真源，两个文件**逐字节不动**，这样它们的 sha256 能一直和线上比对：
出问题时能立刻判断是「文件被改了」还是「线上内容变了」。新内容需要的改动另写增量文件，构建时拼装：

| | 线上产物（逐字节不动） | 增量文件 | 最终产物 |
| --- | --- | --- | --- |
| 样式 | `live/styles.css` | `addon.css`：只新增类，不覆盖线上已有类 | 线上 + 追加 |
| 脚本 | `live/app.js` | `app-delta.js`：登记式替换，每处必须命中恰好一次 | 线上 + 替换 |

脚本没法像样式那样「追加」（要改的是 IIFE 内部的函数），所以改成**登记式精确替换**。
`npm run check` 会断言「产物脚本逐字节等于线上脚本 + 已登记增量」——换错版本或某处替换对不上，构建直接失败。

### 3.3 三道门禁

| 门禁 | 拦什么 |
| --- | --- |
| `check-dist.js` | 死链、SEO 元素缺失、图标缺失、旧品牌残留、sitemap 覆盖、脚本增量等式 |
| `check-facets.mjs` | 把**产物里**的筛选函数取出来配 DOM 桩真的点一遍（多值取或 / 空结果 / 复位） |
| `check-sections.mjs` | 用户明确要求过的区块结构：模块先后与落点、频道卡数量、筛选条吸顶与否 |

## 四、本地构建与校验

### 4.1 环境要求

- **Node.js ≥ 18**，不需要 `npm install`（没有任何第三方依赖）
- 截图 / 冒烟测试需要系统里有 Chrome 或 Edge（可用 `CHROME_PATH` 指定）

### 4.2 常用命令

```bash
npm run build      # 生成 dist/（唯一必须的命令）
npm run check      # 提交前必跑：产物校验 + 筛选核对
npm run sections   # 区块结构核对：模块先后与落点、频道卡、筛选条（需浏览器）
npm run margins    # 版心与左右留白核对：所有页面（需浏览器）
npm run smoke      # 运行时冒烟：真浏览器加载各页，验证主题状态机（需浏览器）
npm run shots      # 视觉核对截图 → redesign/_preview/v2/（明/暗 × 桌面/真机宽度）
npm run urls       # URL 稳定性：线上 sitemap 已有地址，本地是否全部保留
```

> Windows PowerShell 里如果 `npm` 报「禁止运行脚本」，用 `npm.cmd run build`
> 或直接 `node redesign/build.mjs` 即可，详见 [`redesign/README.md`](redesign/README.md)。

### 4.3 部署

`npm run build` 之后把整个 `redesign/dist/` 目录上传到 **EdgeOne Pages** 即可（纯静态，无服务端）。
页面里的相对链接都是站内相对路径，放在任意域名与子目录下都能正常工作。

### 4.4 内容与数据维护

| 想改什么 | 改哪里 |
| --- | --- |
| 站名、域名、备案、联系方式、导航、频道入口、首页承诺、广告位、统计 ID | `redesign/site.config.json` |
| 某个条目的展示名、分类、一句话定位、收录状态（`ok` / `review` / `exclude`） | `redesign/curation.json` |
| AI 工具、技能、运营指南、标签规则、专题清单 | `redesign/content/` |
| 仓库地址、Star、协议、图标直链等**核实结果** | `redesign/data/github.json` |
| 每日新条目的发现与下载 | `redesign/tools/daily/`，见 [`tools/daily/README.md`](redesign/tools/daily/README.md) |

每日流水线（`npm run daily` 等）会自动发现候选、核实仓库、下载并解析包信息、生成审核表与上传目录；
**上传网盘与建立分享链接是手动步骤**，之后用 `daily:links` / `daily:publish` 回填链接并重建站点。
需要联网的命令（`verify` / `icons` / `daily:*` / `baidu:push`）不配 Token 也能跑，只是配额低或需要人工确认。

## 五、目录结构

```
.
├── package.json                命令入口（34 个脚本）
├── .kb-raw.json                从 xlsx 抽取出的原始条目
├── GitHub开源软件分享知识库.xlsx  最初的素材表
├── UPGRADE-PLAN.md             改版与排查过程中的工程记录（含踩坑与结论）
├── _analysis/                  参考站的信息架构 / UI 分析（设计决策的依据）
└── redesign/                   ← 站点工程本体
    ├── build.mjs               站点生成器：读数据 → 直出全部 HTML（无框架、无模板引擎）
    ├── site.config.json        品牌与站点级配置
    ├── curation.json           编辑策展层（展示名 / 分类 / 定位 / 收录状态）
    ├── content/                内容层：tool（AI 工具）/ skill（技能）/ guide（指南）/ tags / topics
    ├── data/github.json        联网核实结果（仓库 / Star / 协议 / 图标直链）
    ├── src/                    设计系统源码与前端增强（保留演进用，构建以 live/ 为真源）
    ├── live/                   线上产物 + 增量：styles.css / app.js / addon.css / app-delta.js
    ├── assets/                 icons/ 真实应用图标（本地落地，不热链）· og.png 分享图
    ├── tools/                  构建、校验、采集工具（见下）
    ├── _preview/               视觉核对截图产物（不入库）
    └── dist/                   ← 部署产物，整个目录上传
```

`redesign/tools/` 里的常驻工具：

| 工具 | 作用 |
| --- | --- |
| `check-dist.js` / `check-facets.mjs` / `check-sections.mjs` / `check-margins.mjs` | 上表的三道门禁 + 版心核对 |
| `smoke.mjs` / `shots.mjs` / `chrome.mjs` | 运行时冒烟、视觉核对截图、无头浏览器封装 |
| `verify-repos.mjs` | 走 GitHub API 核实仓库信息 |
| `fetch-icons.mjs` | 抓取应用图标（魔数校验 + 镜像兜底） |
| `extract-kb.ps1` | 从 xlsx 重新抽取原始条目 |
| `daily/` | 每日采集流水线（发现 → 核实 → 下载解析 → 审核表 → 回填发布） |
| `baidu-push.mjs` / `submit-sitemap.mjs` / `check-index.mjs` / `check-quota.mjs` | 搜索引擎收录相关（需 Token） |
